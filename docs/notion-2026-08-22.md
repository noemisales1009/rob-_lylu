## 🔍 O caso do pontinho branco (diagnóstico completo)

- Um ponto branco **fixo** apareceu no canto da tela → suspeita de pixel defeituoso.
- Evidência decisiva: ele está **exatamente no primeiro pixel (0,0)**. Defeito de fábrica poderia cair em qualquer um dos 230 mil pixels — cair justo no primeiro é assinatura de **artefato de temporização** (o reinício do quadro "vaza" um pixel aceso), efeito colateral conhecido do bounce buffer nessas placas RGB.
- Testamos a cura clássica `pclk_active_neg = 1` → **piorou** (imagem deslocada + tremor) → revertido na hora. Anotado no código: *não usar nesta placa*.
- **Veredito: o display NÃO tem defeito.** O pontinho é cosmético, estável, e a moldura da case impressa vai cobri-lo.
- Ajuste ainda não testado (para um dia calmo): `de_idle_high` / `pclk_idle_high`.

## 👻 Observação guardada: toques fantasmas

Durante o teste de tela preta, o touch reportou toques sozinho na borda extrema (`x=480`, ninguém tocando). Se algum dia uma tarefa "se marcar sozinha", é isso — filtra-se ignorando toques com x ≥ ~475 (1 linha de código).

## 🔄 DECISÃO: migrar para a placa JC4827W543C_I

O slot SD da ESP32-4848S040C não reconhece cartão. Decisão da Noemi: mudar o projeto para a outra placa que já tem em mãos — **Guition JC4827W543C_I** (ESP32-S3, tela 4.3", touch capacitivo, 480×272).

**Por que é um upgrade de estabilidade:** o display dela é QSPI com memória de vídeo própria (NV3041A) — não existe a disputa pela PSRAM que causou o tremor, a faixa e o pontinho. Esses problemas são **fisicamente impossíveis** nessa arquitetura.

**Preço honesto:** tela menor (480×272, paisagem) → layout precisa ser redesenhado; a Lylu de 150px fica grande na tela (dá pra re-exportar a arte menor depois se incomodar).

### Pinagem confirmada (3 fontes: atomic14, profi-max, Arduino_GFX #557)

| Item | Valor |
|---|---|
| Display NV3041A via QSPI | CS=45, SCK=47, D0=21, D1=48, D2=40, D3=39 |
| Luz de fundo | GPIO 1 |
| Touch GT911 (I2C) | SDA=8, SCL=4, INT=3, RST=38 |
| PSRAM | 8 MB |
| Manha conhecida | Precisa inversão de cor + troca de bytes (a chave `TELA_INVERTE_CORES` do sketch já resolve); só rotação 0°/180° |
| Biblioteca | GFX_Library_for_Arduino 1.6.7 instalada já suporta (Arduino_NV3041A + Arduino_ESP32QSPI) |

### ⚠️ Ponto crítico a verificar ANTES de portar

Fontes da comunidade indicam que essa placa pode ter só **4 MB de flash** (a 4848 tem 16). Nossos 168 quadros ocupam 7,4 MB. Existem lotes diferentes — **é preciso medir a flash real** com esptool assim que plugar (segundos, sem gravar nada).

- **Se 16 MB** → porta direto: mesmas imagens no LittleFS, mesma estrutura.
- **Se 4 MB** → as imagens vão pro **cartão SD** (nessa placa o slot é documentado e usado pela comunidade — ironia: o SD volta a ser útil).
